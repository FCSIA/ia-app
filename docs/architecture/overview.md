## What Is Full Stack?

"Full stack" means the project contains two separate programs that communicate with each other over the network:

| Layer | What it is | Technology |
|-------|-----------|------------|
| **Backend** | Convex functions, auth integration, storage, and data access | [[convex\|Convex]] |
| **Frontend** | Browser program. Shows the UI, subscribes to backend data | [[frontend-overview\|Next.js]] |
| **Database** | Convex document tables and file storage | [[schema\|Convex schema]] |

```
Browser (Next.js)  ──→  Convex React client  ──→  Convex functions/database
```

Convex is the **single source of truth**. The browser calls typed Convex queries,
mutations, and actions; authorization still happens server-side in Convex
functions.

## The Monorepo

A **monorepo** (mono = one) puts all apps in a single git repository so they're easier to manage together.

```
ia-app/                     ← one git repo
├── apps/
│   ├── api/                ← legacy NestJS backend reference during the Convex port
│   ├── convex/            ← Convex backend app
│   │   ├── convex.json     ← sets Convex functions path to src/
│   │   ├── seed-data/      ← Convex-owned seed fixtures
│   │   └── src/            ← Convex functions and generated types
│   └── web/                ← web frontend
├── packages/
│   └── contracts/          ← transitional shared types; delete when no longer needed
├── package.json            ← root configuration
├── pnpm-workspace.yaml     ← declares all apps as one workspace
└── turbo.json              ← task runner config
```

- Convex-generated API types are the default source of backend/frontend type
  safety.
- Keep `packages/contracts/` only for small shared product types that are not
  generated by Convex.
- Run all dev servers with one command (`pnpm dev`)
- Manage all dependencies from one place
- See [[convex]] for why Convex uses `apps/convex/src/` instead of the default
  root-level `convex/` directory.

### pnpm

**pnpm** is the package manager — it downloads third-party code (called "packages" or "dependencies") that your apps rely on. When you run `pnpm install`, it reads every `package.json` and downloads everything listed.

Think of it like an app store for code libraries.

### Turbo

**Turbo** is a task runner. It reads `turbo.json` and can run the same command (`dev`, `build`, `lint`) across all apps simultaneously, in the right order, with intelligent caching.

```bash
pnpm dev  # Turbo starts web and Convex/backend dev tasks
```

## How the Apps Communicate

Most app communication happens through the Convex React client.

The frontend subscribes to queries and calls mutations:

```tsx
const user = useQuery(api.users.me.me);
const updateLayout = useMutation(api.users.profile.updateDashboardLayout);
```

Better Auth owns login/session cookies, and `ConvexBetterAuthProvider` supplies
Convex auth tokens for function calls. See [[data-flow]] for a full trace.
